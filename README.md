# Students Database CRUD API

A Python backend for managing student records, built with **FastAPI** and **SQLite**,
for the EWB Edu Tech internship assignment. Includes the optional **Ollama** bonus
(natural-language questions about the data).

All data in this project is **dummy data**. Do not commit real student information.

## Features

- Create, Read (list, filter, single), Update (PUT and PATCH) and Delete students
- SQLite persistence (`students.db` is created automatically on first run)
- Input validation (email format, phone format, DOB in the past, at least one contact method, enrollment not before birth)
- Proper errors: `404` for missing records, `409` for duplicate email, `422` for invalid input
- Auto-generated interactive docs at `/docs`
- Automated test suite (13 tests)
- Optional AI endpoint `POST /ai/ask` using a local Ollama model

## Prerequisites

- Python 3.10 or newer
- (Optional, for the AI bonus) [Ollama](https://ollama.com/download)

## Installation

```bash
git clone <your-repo-url>
cd students-crud

python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate

pip install -r requirements.txt
```

## Run

```bash
python seed.py                   # optional: load 6 dummy students
uvicorn app.main:app --reload
```

Open **http://127.0.0.1:8000/docs** to try every endpoint in the browser.

The database file defaults to `students.db`; override with `STUDENTS_DB=/path/to/file.db`.

## Student fields

| Field | Required | Notes |
|---|---|---|
| `id` | auto | Unique, generated by the database |
| `name` | yes | 1-100 chars, not blank |
| `date_of_birth` | yes | `YYYY-MM-DD`, must be in the past |
| `email` | one of email/phone | Valid format, must be unique |
| `phone` | one of email/phone | 7-20 chars: digits, spaces, `+ - ( )` |
| `course` | no | |
| `address` | no | |
| `enrollment_date` | no | `YYYY-MM-DD`, not before date of birth |

## API endpoints

| Method | Endpoint | Purpose | Success |
|---|---|---|---|
| POST | `/students` | Create a student | 201 |
| GET | `/students` | List / filter students | 200 |
| GET | `/students/{id}` | View one student | 200 |
| PUT | `/students/{id}` | Replace all details | 200 |
| PATCH | `/students/{id}` | Update only the sent fields | 200 |
| DELETE | `/students/{id}` | Delete a student | 204 |
| POST | `/ai/ask` | (Optional) Ask a question via Ollama | 200 |

**List filters** (query params, combinable): `name` (partial), `course` (partial), `email` (exact),
`born_after`, `born_before` (`YYYY-MM-DD`), `skip`, `limit`.

## Testing the API with curl

```bash
# Create
curl -X POST http://127.0.0.1:8000/students \
  -H "Content-Type: application/json" \
  -d '{"name":"Priya Verma","date_of_birth":"2005-04-20","email":"priya@example.com","course":"Python Backend"}'

# List all / filter
curl http://127.0.0.1:8000/students
curl "http://127.0.0.1:8000/students?course=python&born_after=2004-12-31"

# Get one
curl http://127.0.0.1:8000/students/1

# Partial update
curl -X PATCH http://127.0.0.1:8000/students/1 \
  -H "Content-Type: application/json" -d '{"course":"Data Science"}'

# Full update
curl -X PUT http://127.0.0.1:8000/students/1 \
  -H "Content-Type: application/json" \
  -d '{"name":"Priya Verma","date_of_birth":"2005-04-20","phone":"+91 90000 12345"}'

# Delete
curl -X DELETE http://127.0.0.1:8000/students/1

# Missing record -> 404
curl -i http://127.0.0.1:8000/students/9999
```

## Optional: AI questions with Ollama

1. Install Ollama and pull a small model:
   ```bash
   ollama pull llama3.2:1b
   ollama serve        # skip if Ollama is already running as a service
   ```
2. Start the API and ask questions:
   ```bash
   curl -X POST http://127.0.0.1:8000/ai/ask \
     -H "Content-Type: application/json" \
     -d '{"question":"How many students are there?"}'

   curl -X POST http://127.0.0.1:8000/ai/ask \
     -H "Content-Type: application/json" \
     -d '{"question":"List students born after 2005"}'
   ```

Config via environment variables: `OLLAMA_HOST` (default `http://localhost:11434`),
`OLLAMA_MODEL` (default `llama3.2:1b`).

### How it stays safe and accurate

- The model **never writes or runs SQL**.
- Backend code (`app/ai.py`) detects what the question is about (total count, born after/before/in a year,
  course name, student name) and fetches matching rows with **fixed, parameterized queries**.
- The records plus pre-computed facts (e.g. total count, number of matches) are passed to the model as context,
  and the prompt tells it to answer only from that context.
- Temperature is 0 for consistent answers. If Ollama isn't running, the endpoint returns a clear `503` message.

## Architecture summary

1. **Route layer** (`main.py`) receives the request and FastAPI/Pydantic validates it.
2. **Schema layer** (`schemas.py`) enforces business rules and returns `422` on bad input.
3. **CRUD layer** (`crud.py`) runs parameterized SQL against SQLite and returns plain dicts.
4. Missing records give `404`; a duplicate email triggers SQLite's `UNIQUE` constraint, mapped to `409`.
5. PATCH merges the sent fields onto the stored record and re-validates the whole result before saving.
